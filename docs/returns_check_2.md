#### 4.4.2 How advance recoveries work

```
Prior months: Agent pays expenses → debits cb_landlord_account (CHLACC)
               e.g., LOAN 500,000 → CHLACC debit entry_type_code 0020

March return:  CHRTXS lists each prior advance as a DR line
               → these are the "Advance Payments-From Landlord Acc" entries
               → net_amount shows what's being offset/recovered

CHLACC POST (0005 RETURNS credit):
  1,738,400 (total_credit) − 105,684 (commission) − 21,800 (recoveries)
  = 1,610,916  ← what CHABRINS posts to the landlord account as RETURNS credit

Prior CHLACC debit balance from advances: 1,523,904
CHLACC net after return credit: 1,610,916 − 1,523,904 = 87,012 → landlord receives 87,012 ✓
```

> **Important:** The advance amounts are NOT re-debited in CHLACC when the return is processed —
> they were already charged in earlier CHLACC entries. The CHRTXS lines are the reconciliation
> narrative showing which advances are being offset. `net_amount` is correct; `total_debit` is
> intentionally understated (mirrors CHABRINS TOTALDR behaviour).

## 8. Systemic Data Issues (Migrated Returns)

All issues below apply to both returns and are **migration artefacts**, not bugs in CHIPS.

| #   | Issue                                                                        | Impact                                              | Root Cause                                                                             |
| --- | ---------------------------------------------------------------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 1   | `total_debit` excludes Advance Payments                                      | 127,484 vs actual 1,651,388                         | CHABRINS TOTALDR never included advances in that field; NETAMT was computed separately |
| 2   | `payable_amount`, `total_units`, `payable_units`, `non_payable_amount` all 0 | Unit-level reporting broken for old returns         | Columns added to CHIPS after migration; never backfilled                               |
| 3   | `commission_amount = 0` on individual rent lines                             | Can't report per-unit commission breakdown          | CHABRINS stored commission as single summary DR line; not per-unit                     |
| 4   | `cb_money_recoveries` = 0 rows for migrated returns                          | Recovery detail only in `cb_returns_clients`        | `cb_money_recoveries` table not populated during migration                             |
| 5   | `pv_number = NULL` on `cb_landlord_account` entries                          | Can't trace ledger entries back to payment vouchers | Not populated during migration                                                         |

> `net_amount` and `amount_paid` are **always correct** — these were taken directly from CHABRINS NETAMT/AMTPAYD, which were correctly computed at source.
