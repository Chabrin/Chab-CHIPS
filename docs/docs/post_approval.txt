## 🎯 OVERVIEW

This document details the **complete workflow** that occurs **AFTER** a return reaches final approval in the approval chain. It covers what happens from the moment the final approval is granted through to the actual payment voucher generation and GL posting.

### Key Stages:

1. **Approval Trigger** - Final approval granted (determinant='Yes')
2. **Landlord Ledger Credit** - Return amount credited to landlord account
3. **Payment Distribution** - Eligible returns selected for payment batch
4. **Batch Processing** - Returns grouped by property/landlord configuration
5. **GL Posting** - General ledger entries created
6. **Payment Voucher** - Bank payment vouchers generated

## 📌 STAGE 1: APPROVAL TRIGGER

### When It Happens

- Final approval step in workflow chain
- Approval action has `determinant = 'Yes'` flag
- Return has passed all required approval levels

### What Happens

**Service:** `ClientReturnService::processWorkflow($action_data)`

**Location:** `libraries/ipms/Domain/Service/ClientReturnService.php:18-77`

**Code Flow:**

```php
public static function processWorkflow($action_data)
{
    $final = $action_data->determinant;

    if($final == 'Yes'){
        // This is the FINAL approval step

        // 1. Update return status to Approved
        $params = array('id' => $action_data->trans_id);
        $values = array('current_status_id' => $action_data->action_id);
        (new ClientReturnRepository())->updateVals($values, $params);

        // 2. Credit landlord ledger
        $landlord_service = new LandlordTransService();
        $landlord_service->createFromReturn($action_data->trans_id);

    } else {
        // Intermediate approval - continue workflow
        WorkFlowService::genericProcessWorkflow($action_data);
    }
}
```

### Tables Updated

**sys_pm_clients_returns:**

- `current_status_id` = 5 (Approved)

**sys_workflow_activities:**

- New record created with approval details
- `action_id` = approved status
- `actioned_by` = user who approved
- `actioned_date` = timestamp

## 💰 STAGE 2: LANDLORD LEDGER CREDIT ENTRY

### When It Happens

- Immediately after final approval is granted
- Called by `ClientReturnService::processWorkflow()`

### What Happens

**Service:** `LandlordTransService::createFromReturn($return_id, $posted_status_id = 1)`

**Location:** `libraries/ipms/Domain/Service/LandlordTransService.php:1126-1207`

### Main Credit Entry

Creates a **CREDIT** entry in landlord's ledger representing the return amount owed to the landlord.

```php
public function createFromReturn($return_id, $posted_status_id = 1)
{
    if($return = $this->clientReturnRepository->getById($return_id)){

        $data = new stdClass();
        $data->date_time = date('Y-m-d H:i:s');
        $data->trans_date_time = $return->getReturnDate()->format('Y-m-d H:i:s');
        $data->client_id = $return->getClient()->getId();
        $data->property_id = $return->getProperty()->getId();
        $data->origin_id = '33:'.$return->getId().':'.time();
        $data->transaction_type_id = 13; // Client Return
        $data->narration = 'Return Payable Unit - '.$unit_code;
        $data->amount_type = 'Credit';
        $data->amount = $return->getTransAmount();
        $data->unit_id = $return->getUnit()->getId();
        $data->lease_id = $return->getLease()->getId();
        $data->tenant_id = $return->getTenant()->getId();
        $data->current_status_id = $posted_status_id;
        $data->sla_id = $return->getSla()->getId();

        // IMPORTANT: Initially created as UNPAYABLE (payable_status = 0)
        // This will be updated when tenant pays invoice

        $this->landlordTransRepository->persist($data);
    }
}
```

**Table:** `sys_pm_landlord_accounts_transaction`

**Fields:**

| Field               | Value                    | Notes                                       |
| ------------------- | ------------------------ | ------------------------------------------- |
| amount_type         | 'Credit'                 | Money owed TO landlord                      |
| amount              | trans_amount             | Full return amount                          |
| transaction_type_id | 13                       | Client Return type                          |
| payable_status      | 0                        | Initially UNPAYABLE (excluded from balance) |
| current_status_id   | 1                        | Pending                                     |
| origin_id           | '33:return_id:timestamp' | Links back to return record                 |
| client_id           | landlord ID              | Owner of property                           |
| property_id         | property ID              | Property generating return                  |
| unit_id             | unit ID                  | Specific unit                               |
| lease_id            | lease ID                 | Current lease                               |
| tenant_id           | tenant ID                | Current tenant                              |
| invoice_id          | invoice ID               | Associated tenant invoice                   |
| sla_id              | SLA ID                   | Service level agreement                     |
| trans_date_time     | return_date              | Date of return                              |

### Commission Debit Entry (If Applicable)

If return has commission charges, a **DEBIT** entry is also created:

```php
if($return->getComm()){
    if($comm_amount = $return->getComm()){
        $commission_data->amount = '-'.$comm_amount;
        $commission_data->amount_type = 'Debit';
        $commission_data->origin_id = $commission_data->origin_id.':'.time();
        $commission_data->transaction_type_id = 21; // Commission Charge
        $commission_data->narration = 'Commission Charge Unit - '.$unit_code;

        $this->landlordTransRepository->persist($commission_data);

        // GL Entry: Credit commission revenue account
        if($rent_commission_account_id = (new GLAccountsDao())->getGLSettings()->rent_commission_account_id){
            $journal_items[] = array(
                'account_id' => $rent_commission_account_id,
                'narration' => $commission_data->narration,
                'amount' => '-'.abs($comm_amount),
                'entry_type' => 'Credit'
            );
        }
    }
}
```

**Result:**

- Landlord credited with return amount
- Commission deducted from landlord
- GL entries created for commission revenue
- Return linked to landlord ledger via `origin_id`

## 🔄 STAGE 3: PAYMENT DISTRIBUTION GENERATION

### When It Happens

- After tenant makes payment on associated invoice
- Payment threshold calculation triggered
- Monthly batch generation process

### Payable Status Update

**Trigger:** `ClientReturnService::updateReturnOnInvoicePayment($invoice_id)`

**Location:** `libraries/ipms/Domain/Service/ClientReturnService.php:523-897`

### Threshold Calculation Logic

```sql
-- Calculate payment threshold
SELECT
    inv.id,
    inv.total_amount,
    (inv.total_amount - inv.current_balance) as paid_amount,
    ROUND(((inv.total_amount - inv.current_balance) / inv.total_amount) * 100, 2) as payment_threshold
FROM sys_pm_debtors_invoices inv
WHERE inv.id = :invoice_id
```

**Payability Rules:**

| Condition                     | Result    | payable_status_id |
| ----------------------------- | --------- | ----------------- |
| payment_threshold >= 85%      | PAYABLE   | 1                 |
| invoice fully cleared         | PAYABLE   | 1                 |
| previous month return met 85% | PAYABLE   | 3                 |
| first invoice (no history)    | PAYABLE   | 2                 |
| payment_threshold < 85%       | UNPAYABLE | 0                 |

### Update Return Payable Status

```php
// Update return record
UPDATE sys_pm_clients_returns
SET payable_status_id = 1,  -- Payable
    payable_amount = :payable_amount
WHERE invoice_id = :invoice_id
```

### Sync Landlord Ledger

```php
// Update landlord ledger entry
UPDATE sys_pm_landlord_accounts_transaction
SET payable_status = 1  -- Include in balance calculation
WHERE invoice_id = :invoice_id
  AND transaction_type_id = 13  -- Client Return
  AND amount_type = 'Credit'
```

**Result:**

- Return marked as PAYABLE
- Landlord ledger credit entry included in balance
- Return now eligible for batch generation

## 📦 STAGE 4: BATCH PROCESSING

### When It Happens

- Monthly batch generation initiated
- After returns are approved and payable
- Triggered manually or via cron job

### Batch Creation

**Service:** `ReturnBatchService::createBatch($property_report_id)`

**Location:** `libraries/ipms/Domain/Service/ReturnBatchService.php`

### Batch Grouping Logic

Returns are grouped into batches based on:

1. **Property Configuration:** `sys_eports_returns_batches_configurations`
2. **Bank Account Settings:** Payout account assignments
3. **Period:** Month/Year of return generation
4. **Client:** Landlord owner

```sql
-- Find batch configuration for property
SELECT
    bc.id as batch_config_id,
    bc.configuration_name,
    pbc.id as parent_batch_config_id
FROM sys_eports_returns_batches_configurations_298_repeat_repeat_prs properties
INNER JOIN sys_eports_returns_batches_configurations_298_repeat bc
    ON bc.id = properties.parent_id
INNER JOIN sys_eports_returns_batches_configurations pbc
    ON pbc.id = bc.parent_id
WHERE properties.prs = :property_id
```

### Batch Totals Calculation

```sql
-- Calculate batch totals
SELECT
    property_id,
    COUNT(*) as returns_count,
    SUM(trans_amount) as gross_amount,
    SUM(comm_amount) as total_comm,
    SUM(comm_vat) as total_vat,
    SUM(CASE WHEN recovery_id IS NOT NULL THEN amount ELSE 0 END) as total_recoveries,
    (SUM(trans_amount) - SUM(comm_amount) - SUM(comm_vat) - SUM(recoveries)) as net_amount
FROM sys_pm_clients_returns
WHERE payable_status_id = 1  -- Payable only
  AND current_status_id != 17  -- Not already processed
  AND return_date BETWEEN :start_date AND :end_date
GROUP BY property_id
```

### Tables Involved

**sys_reports_returns_batches:**

- Batch header record
- Contains totals and status

**sys_reports_returns_batches_repeat_returns_id:**

- Junction table linking returns to batch

**sys_reports_returns_batches_repeat_property_report_id:**

- Junction table linking property reports to batch

**sys_reports_returns_batches_283_repeat:**

- Bank account payout configuration
- Percentage splits per account

## 📝 STAGE 5: GL POSTING

### When It Happens

- Batch approval granted (determinant='Yes')
- Part of `ReturnBatchService::processWorkflow()`

### GL Entry Creation

**Service:** `ReturnBatchService::postGl($action_data)`

**GL Service:** `GLTransService::makeJournalEntry($gl_data)`

### Journal Entries

```php
$journal_items = array();

// DEBIT: Clients Account (Landlord Receivable)
if($clients_account_id = (new GLAccountsDao())->getGLSettings()->clients_account_id){
    $journal_items[] = array(
        'account_id' => $clients_account_id,
        'narration' => 'Client Period Payment',
        'amount' => $action_data->amount,  // net_amount (positive)
        'entry_type' => 'Debit'
    );
}

// CREDIT: Clients Payable Account (Landlord Payable)
if($clients_payable_account_id = (new GLAccountsDao())->getGLSettings()->clients_payable_account_id){
    $journal_items[] = array(
        'account_id' => $clients_payable_account_id,
        'narration' => 'Client Period Payment',
        'amount' => '-'.$action_data->amount,  // -net_amount (negative)
        'entry_type' => 'Credit'
    );
}

$gl_data = array(
    'journal_date' => $action_data->trans_date_time,
    'entered_by' => JFactory::getUser()->id,
    'trans_type_id' => $action_data->transaction_type_id,  // 18 = Client Period Payment
    'trans_details' => $action_data->origin_id,  // '125:batch_id'
    'journal_items' => $journal_items,
    'direct_post' => false  // Must balance
);

GLTransService::makeJournalEntry($gl_data);
```

**GL Accounts Affected:**

| Account                      | Entry Type | Amount      | Description                     |
| ---------------------------- | ---------- | ----------- | ------------------------------- |
| Clients Account (Receivable) | DEBIT      | +net_amount | Reduce amount owed to landlords |
| Clients Payable Account      | CREDIT     | -net_amount | Reduce liability to landlords   |

**Result:**

- GL entries created in `sys_gl_entries`
- Accounts balanced
- Transaction auditable via `trans_details`

```php
    }
}
```

## 🔄 STATUS TRANSITIONS

### Return Status Flow

```
sys_pm_clients_returns.current_status_id

1 (Pending)
    → Generated but not approved

5 (Approved)
    → Final approval granted
    → Triggers landlord ledger credit

17 (Processed)
    → Included in payment batch
    → Payment voucher created
    → Final state
```

### Payable Status Flow

```
sys_pm_clients_returns.payable_status_id

0 (Unpayable)
    → Tenant paid < 85% of invoice
    → Excluded from balance calculation

1 (Payable)
    → Tenant paid ≥ 85% of invoice
    → Included in balance calculation
    → Eligible for batch generation

2 (No Past Invoice)
    → First invoice (no payment history)
    → Automatically payable

3 (Past Passed Threshold)
    → Previous month return met 85%
    → Current return payable even if < 85%

17 (Processed)
    → Already paid to landlord
    → Payment complete
```

### Paid Status Flow

```
sys_pm_clients_returns.paid_status_id

1 (Pending)
    → Payable but not yet paid

2 (Paid)
    → Payment voucher created
    → Money transferred to landlord

6 (Posted)
    → GL entries completed
    → Fully posted to accounts
```

### Landlord Ledger Status Flow

```
sys_pm_landlord_accounts_transaction.payable_status

0 (Unpayable)
    → Excluded from balance calculation
    → Return not eligible for payment

1 (Payable)
    → Included in balance calculation
    → Return eligible for payment

17 (Processed)
    → Already paid out
    → Included in balance but marked processed
```

### Batch Status Flow

```
sys_reports_returns_batches.current_status_id

1 (Pending)
    → Batch created but not approved

5 (Approved)
    → Final approval granted
    → Triggers GL posting and voucher creation

6 (Posted)
    → GL entries completed

17 (Processed)
    → Payment vouchers generated
    → Final state
```

## 🎯 SUMMARY

### Complete Journey of a Return

1. **Created** - Return generated from tenant invoice
2. **Pending** - Awaiting approval(s)
3. **Approved** - Final approval granted (determinant='Yes')
4. **Landlord Credited** - Credit entry created in landlord ledger
5. **Becomes Payable** - When tenant pays ≥ 85% of invoice
6. **Batch Generated** - Grouped with other returns for payment
7. **Batch Approved** - Batch workflow approval granted
8. **GL Posted** - Accounting entries created
9. **Voucher Created** - Payment voucher(s) generated for bank transfer
10. **Processed & Paid** - Final status, money transferred to landlord

### Key Points

✅ **Approval triggers landlord ledger credit** - Immediately upon final approval

✅ **Payability is separate from approval** - Return must be approved AND invoice must meet payment threshold

✅ **Batch processing groups returns** - Multiple returns paid together per landlord/property configuration

✅ **GL posting is automatic** - Happens during batch approval

✅ **Multiple vouchers per batch** - If landlord has multiple payout accounts

✅ **Complete audit trail** - Every step logged in `sys_workflow_activities`

✅ **Status synchronization** - Return status, landlord ledger status, and batch status all updated together
