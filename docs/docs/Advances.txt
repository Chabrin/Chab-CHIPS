# CLIENT/LANDLORD ADVANCES SYSTEM

## Overview

The Advances system allows property management companies to issue **loans/advances** to landlords/clients. These advances are repaid through **monthly deductions from property returns**. The system handles:

1. Advance issuance with amortization schedules
2. Interest calculations (simple or compound)
3. Approval workflows
4. Automatic monthly repayments (principal + interest)
5. Deductions from returns
6. General Ledger postings
7. Payment voucher generation

### 8. **`sys_gl_journal_entries`** & **`sys_gl_journal_items`** - General Ledger

**Purpose:** Journal entries for advances (double-entry accounting)

**On Disbursement:**

- **Debit**: Loans Receivable (Asset)
- **Debit**: Interests Receivable (Asset)
- **Credit**: Clients Advance Loans Payable (Liability)
- **Credit**: Loan Interests Revenue (Revenue)

**On Repayment:**

- **Debit**: Clients Account (Liability - reduce what we owe client)
- **Credit**: Loans Receivable (Asset - reduce receivable)
- **Credit**: Interests Receivable (Asset - reduce receivable)

## 🔄 Advance Workflow

### Phase 1: Advance Creation & Approval

```
┌────────────────────────────────────────────────────────────────┐
│                   ADVANCE CREATION WORKFLOW                     │
└────────────────────────────────────────────────────────────────┘

STEP 1: Create Advance Requisition
│
├─> User/Admin creates advance request
│   - Client selection
│   - Amount (e.g., KSh 100,000)
│   - Interest rate (e.g., 2% monthly)
│   - Repayment months (e.g., 10 months)
│   - Disbursement date
│   - Principal start date (when repayment begins)
│
└─> System calculates amortization schedule
    - Calls: LoansAdvancesService::ajaxArmotizeNewLoan()
    - Generates monthly schedule (principal + interest)
    - Stores in sys_pm_clients_advances_requisitions_89_repeat

▼

STEP 2: Approval Workflow
│
├─> Advance submitted for approval
│   - Status: Pending (1)
│   - Task created for approver
│
├─> Approver reviews and approves
│   - Calls: LoansAdvancesService::processWorkflow()
│   - Status: Approved (5)
│
└─> System triggers:
    1. Client Statement Entry (debit client account)
    2. General Ledger Posting
    3. Payment Voucher Generation

▼

STEP 3: Disbursement
│
├─> GL Posting (recordGL)
│   DR: Loans Receivable ............ 100,000
│   DR: Interests Receivable ........ 10,000
│       CR: Clients Advance Loans Payable ... 100,000
│       CR: Loan Interests Revenue ........... 10,000
│
├─> Client Statement
│   - Table: sys_reports_landlord_accounts
│   - Debit: 110,000 (principal + interest)
│   - Origin: "29:advance_id"
│   - Transaction Type: 15 (Client Advance)
│
└─> Payment Voucher Created
    - Table: sys_fin_payment_vouchers
    - Amount: 100,000
    - Payee: Client Name
    - Status: Pending
    - Links to cheque/bank transfer for actual payment
```

### Phase 2: Monthly Repayments (Automatic via Cron)

```
┌────────────────────────────────────────────────────────────────┐
│              MONTHLY REPAYMENT DEDUCTION PROCESS                │
└────────────────────────────────────────────────────────────────┘

CRON JOB: LoansAdvancesService::recoverLoans()
Runs: Monthly (typically after invoices are generated)

▼

STEP 1: Identify Matured Schedules
│
├─> Query: getAllMatured()
│   SELECT * FROM sys_pm_clients_advances_requisitions
│   WHERE MONTH(principal_start_date) <= CURRENT_MONTH
│   AND YEAR(principal_start_date) <= CURRENT_YEAR
│   AND current_status_id = 5 (Approved)
│
└─> For each advance, get pending schedules
    Query: getSchedule(advance_id, pending_status)

▼

STEP 2: Process Each Matured Schedule
│
├─> For each schedule where payment_date <= TODAY
│   - Principal amount (e.g., KSh 10,000)
│   - Interest amount (e.g., KSh 2,000)
│
├─> Debit Client Account (Principal)
│   Table: sys_pm_landlord_accounts_transaction
│   - amount: -10,000
│   - transaction_type_id: 23 (Principal Repayment)
│   - origin_id: "29:advance_id:schedule_id"
│   - current_status_id: 6 (Posted)
│
├─> Create Recovery (Principal)
│   Table: sys_pm_recoveries
│   - amount: 10,000 (positive)
│   - type_id: 23 (Principal Repayment)
│   - narration: "Loan/Advance Principal Recovery"
│
├─> Debit Client Account (Interest)
│   Table: sys_pm_landlord_accounts_transaction
│   - amount: -2,000
│   - transaction_type_id: 24 (Interest Payment)
│
├─> Create Recovery (Interest)
│   Table: sys_pm_recoveries
│   - amount: 2,000
│   - type_id: 24 (Interest Payment)
│   - narration: "Loan/Advance Interest charge"
│
└─> Post to General Ledger
    DR: Clients Account ............. 12,000
        CR: Loans Receivable ............. 10,000
        CR: Interests Receivable ......... 2,000

▼

STEP 3: Update Balances & Status
│
├─> Update Schedule
│   - current_status_id: 2 (Cleared)
│
├─> Update Advance Balance
│   - current_balance: old_balance - principal_amount
│
└─> Trigger Returns Regeneration
    - Calls: ClientReturnReportService::preparePropertyReturnsReports()
    - Regenerates returns with recoveries included
```

### Phase 3: Deduction from Returns

```
┌────────────────────────────────────────────────────────────────┐
│         INTEGRATION WITH RETURNS GENERATION PROCESS             │
└────────────────────────────────────────────────────────────────┘

WHEN: Returns are generated for the month

▼

STEP 1: Calculate Gross Returns
│
├─> Sum all invoices paid
├─> Calculate SLA percentages
└─> Calculate gross return per property

▼

STEP 2: Fetch Recoveries (Including Advances)
│
├─> Query: sys_pm_recoveries
│   WHERE client_id = landlord_id
│   AND current_status_id = 5 (Approved)
│   AND recovery_date matches period
│
└─> Includes:
    - Loan principal repayments (type_id=23)
    - Loan interest payments (type_id=24)
    - Other recoveries (repairs, utilities, etc.)

▼

STEP 3: Calculate Net Returns
│
├─> Net Return = Gross Return - Total Recoveries
│   Example:
│   - Gross: KSh 150,000
│   - Commission: -15,000
│   - VAT: -2,400
│   - Loan Principal: -10,000
│   - Loan Interest: -2,000
│   - Other Recoveries: -5,000
│   ─────────────────────────
│   Net Return: KSh 115,600
│
└─> Update Property Return Report
    Table: sys_reports_returns_properties
    - total_recoveries: includes advance repayments
    - total_net_amount: after all deductions

▼

STEP 4: Batch & Payout
│
├─> Group properties into batch
├─> Configure payout accounts
└─> Generate payment voucher with net amount
    (Advance already deducted, landlord receives net)
```

## � Application/Requisition Process

### Who Can Apply

**Initiators:**

- **Admin/Finance Officer** - Primary method (on behalf of client)
- **Client/Landlord** - Self-service application (if system allows)
- **Property Manager** - Can recommend/initiate for clients

**Access Control:**

- User must have "Create Advances" permission
- Client must be active in system
- Client must have at least one property under management

---

### Eligibility Criteria

Before creating an advance requisition, verify client meets these criteria:

#### 1. **Client Status**

- Active client with valid contract
- No suspended or terminated status
- Minimum relationship duration: 3-6 months (configurable)

#### 2. **Financial Standing**

- Minimum average monthly returns: KSh 50,000 (or configured threshold)
- No negative account balance exceeding 3 months
- Debt-to-Income ratio < 60%

#### 3. **Outstanding Advances**

- Maximum concurrent advances: 2 active loans
- Total outstanding balance < 80% of average monthly returns
- No defaulted advances in last 12 months

#### 4. **Property Performance**

- At least 70% occupancy rate (if applicable)
- Regular rent collection pattern
- No properties under dispute

#### 5. **Returns History**

- Minimum 3 consecutive months of returns
- Average monthly return meets minimum threshold
- Consistent payment pattern (85% threshold met regularly)

### Field Validation Rules

#### **Amount**

```php
// Validation logic
$min_amount = 10000; // KSh 10,000
$max_amount = min(5000000, $client_avg_returns * 0.8 * 12); // 80% of annual returns
$existing_balance = getClientOutstandingAdvances($client_id);
$available_amount = $max_amount - $existing_balance;

if ($amount < $min_amount) {
    return "Minimum advance amount is KSh 10,000";
}
if ($amount > $available_amount) {
    return "Amount exceeds available limit. Max: KSh " . number_format($available_amount);
}
```

#### **Interest Rate**

```php
// Validation logic
$min_rate = 0.5; // 0.5% monthly
$max_rate = 5.0; // 5% monthly
$default_rate = 2.0; // 2% monthly

if ($interest_rate < $min_rate || $interest_rate > $max_rate) {
    return "Interest rate must be between {$min_rate}% and {$max_rate}%";
}
```

#### **Repayment Months**

```php
// Validation logic
$min_months = 3;
$max_months = 36;

// Business rule: Max repayment should not exceed amount/avg_monthly_return ratio
$max_affordable_months = floor($amount / ($client_avg_returns * 0.3)); // 30% of returns

if ($repayment_months < $min_months || $repayment_months > min($max_months, $max_affordable_months)) {
    return "Repayment period must be between {$min_months} and {$max_affordable_months} months";
}
```

#### **Date Rules**

```php
// Disbursement date validation
if ($disbursement_date < $requisition_date) {
    return "Disbursement date cannot be before requisition date";
}
if ($disbursement_date > date('Y-m-d', strtotime($requisition_date . ' +30 days'))) {
    return "Disbursement date must be within 30 days of requisition";
}

// Principal start date validation
if ($principal_start_date <= $disbursement_date) {
    return "Principal start date must be after disbursement date";
}

// Recommended: First day of next month
$recommended_start = date('Y-m-01', strtotime($disbursement_date . ' +1 month'));
```

### Business Rules & Calculations

#### **1. Processing Fee (charge_amount)**

**Calculation:**

```php
// Option A: Percentage-based
$charge_amount = $amount * 0.02; // 2% of principal

// Option B: Flat fee
$charge_amount = 5000; // KSh 5,000 flat

// Option C: Tiered
if ($amount < 100000) {
    $charge_amount = 2000;
} elseif ($amount < 500000) {
    $charge_amount = 5000;
} else {
    $charge_amount = $amount * 0.015; // 1.5%
}
```

#### **2. Total Interest Calculation**

**Preview calculation (before submission):**

```php
// Simple estimation for preview
$estimated_interest = ($amount * $interest_rate / 100) * $repayment_months;
$estimated_total = $amount + $estimated_interest;

// Actual calculation happens via amortization (reducing balance)
$actual_interest = calculateAmortizationInterest($amount, $interest_rate, $repayment_months, $disbursement_date, $principal_start_date);
```

#### **3. Maximum Advance Calculation**

**Formula:**

```php
function getMaxAdvanceAmount($client_id) {
    // Get last 6 months average returns
    $avg_monthly_returns = getClientAverageReturns($client_id, 6);

    // Get existing outstanding balance
    $outstanding_balance = getClientOutstandingAdvances($client_id);

    // Calculate max (80% of annual returns)
    $max_annual_advance = $avg_monthly_returns * 12 * 0.8;

    // Available = Max - Outstanding
    $available = $max_annual_advance - $outstanding_balance;

    return max(0, $available);
}
```

#### **4. Debt Service Coverage Ratio (DSCR)**

**Calculation:**

```php
function checkDebtServiceCoverage($client_id, $requested_amount, $repayment_months, $interest_rate) {
    $avg_monthly_returns = getClientAverageReturns($client_id, 6);

    // Calculate estimated monthly payment
    $monthly_payment = calculateMonthlyPayment($requested_amount, $interest_rate, $repayment_months);

    // DSCR = Monthly Returns / Monthly Payment
    $dscr = $avg_monthly_returns / $monthly_payment;

    // Minimum acceptable DSCR: 1.5 (returns should be 1.5x payment)
    if ($dscr < 1.5) {
        return [
            'approved' => false,
            'message' => 'Insufficient returns to support repayment. DSCR: ' . round($dscr, 2)
        ];
    }

    return ['approved' => true, 'dscr' => $dscr];
}
```

### Approval Hierarchy

#### **Level 1: Finance Officer/Loan Officer**

- **Role**: Initial review and verification
- **Checks**:
    - Eligibility criteria met
    - Data accuracy and completeness
    - DSCR calculation verification
    - Credit history check
- **Action**: Approve, Reject, or Request More Info
- **Limit**: Up to KSh 200,000

#### **Level 2: Finance Manager**

- **Role**: Financial assessment
- **Checks**:
    - Risk assessment
    - Cash flow analysis
    - Total exposure to client
    - Portfolio risk management
- **Action**: Approve, Reject, or Escalate
- **Limit**: Up to KSh 1,000,000

#### **Level 3: General Manager/CFO**

- **Role**: Final approval for large amounts
- **Checks**:
    - Strategic alignment
    - Overall company exposure
    - Special considerations
- **Action**: Final Approve or Reject
- **Limit**: Above KSh 1,000,000 or as required

**Escalation Rules:**

- Any advance > KSh 200,000 requires Manager approval
- Any advance > KSh 1,000,000 requires GM/CFO approval
- Rescheduled advances always require Manager+ approval
- Clients with previous defaults require GM/CFO approval

### System Validations

#### **Pre-Submission Checks**

```php
function validateAdvanceApplication($data) {
    $errors = [];

    // 1. Client validation
    if (!isActiveClient($data['client_id'])) {
        $errors[] = "Client is not active";
    }

    // 2. Amount validation
    $max_amount = getMaxAdvanceAmount($data['client_id']);
    if ($data['amount'] > $max_amount) {
        $errors[] = "Amount exceeds available limit of KSh " . number_format($max_amount);
    }

    // 3. DSCR check
    $dscr_check = checkDebtServiceCoverage(
        $data['client_id'],
        $data['amount'],
        $data['repayment_months'],
        $data['interest_rate']
    );
    if (!$dscr_check['approved']) {
        $errors[] = $dscr_check['message'];
    }

    // 4. Outstanding advances check
    $outstanding_count = getClientActiveAdvancesCount($data['client_id']);
    if ($outstanding_count >= 2) {
        $errors[] = "Client already has maximum (2) active advances";
    }

    // 5. Date sequence validation
    if ($data['disbursement_date'] < $data['requisition_date']) {
        $errors[] = "Disbursement date cannot be before requisition date";
    }
    if ($data['principal_start_date'] <= $data['disbursement_date']) {
        $errors[] = "Principal start date must be after disbursement date";
    }

    // 6. Interest rate validation
    if ($data['interest_rate'] < 0.5 || $data['interest_rate'] > 5) {
        $errors[] = "Interest rate must be between 0.5% and 5%";
    }

    // 7. Rescheduling validation
    if ($data['advance_type_id'] == 3 && empty($data['previous_advance_id'])) {
        $errors[] = "Previous advance must be specified for rescheduling";
    }

    return [
        'valid' => empty($errors),
        'errors' => $errors
    ];
}
```

### Tips for Successful Application

✅ **DO:**

- Ensure client has consistent returns history (6+ months)
- Request reasonable amount (< 50% of average monthly returns)
- Choose appropriate repayment period (shorter = less interest)
- Provide clear purpose/narration
- Submit during business hours for faster processing
- Follow up with required documentation

❌ **DON'T:**

- Request amount exceeding available limit
- Choose unrealistic repayment period
- Submit for clients with irregular returns
- Leave narration vague or empty
- Set disbursement date too far in future
- Apply when client has pending defaults

## 🎯 Interest Calculation

### Simple Interest (Monthly)

```php
public static function calculateInterest($principal, $rate, $date)
{
    $year = date('Y', strtotime($date));
    $month = date('m', strtotime($date));
    $days_in_month = cal_days_in_month(CAL_GREGORIAN, $month, $year);

    // Monthly interest
    $monthly_interest = round(($principal * $rate) / 100);

    return $monthly_interest;
}
```

### Amortization Schedule Logic

**Grace Period (Interest Only):**

- If disbursement before 25th of month AND not same month as principal start
- Charge interest only for remaining days/months

**Principal Repayment:**

- Equal principal per month: `principal_per_month = total_principal / repayment_months`
- Interest calculated on reducing balance: `interest = current_balance * rate`
- Balance reduces each month: `new_balance = old_balance - principal_payment`

**Example:**

```
Loan: KSh 100,000 @ 2% per month, 10 months
Disbursement: 2026-01-10
Principal Start: 2026-02-15

Grace Period:
  Jan: Interest only = 2,000 (on 100,000)

Principal Repayment (Starting Feb):
  Month 1: Principal=10,000, Interest=2,000 (on 100,000), Balance=90,000
  Month 2: Principal=10,000, Interest=1,800 (on 90,000), Balance=80,000
  Month 3: Principal=10,000, Interest=1,600 (on 80,000), Balance=70,000
  ...
  Month 10: Principal=10,000, Interest=200 (on 10,000), Balance=0

Total Interest: 2,000 + (2,000+1,800+1,600+...+200) = 13,000
```

    - New schedule starts from first pending date of old advance

## 🔄 Cron Job Schedule

**Function:** `LoansAdvancesService::recoverLoans()`  
**Frequency:** Monthly (typically 1st or 2nd of month)  
**Trigger:** `CronService::recoverLoans()` calls `LoansAdvancesService::recoverLoans()`

**Process:**

1. Find all advances with matured schedules
2. Process each pending schedule
3. Debit client account
4. Create recovery records
5. Post to GL
6. Mark schedule as cleared
7. Update advance balance
8. Trigger returns regeneration

---

## ⚠️ Important Notes

1. **Automatic Deduction**: Advances are **automatically deducted** from returns every month via cron job
2. **Double-Entry Accounting**: All transactions must balance in GL
3. **Client Balance Impact**: Advances immediately debit client account (increase what client owes)
4. **Returns Impact**: Monthly repayments reduce net return amount
5. **Rescheduling**: Old advance is marked "Rescheduled", new advance created with revised terms
6. **Grace Period**: If disbursement before 25th of month, interest-only period may apply
7. **Balance Tracking**: `current_balance` field updated after each repayment
8. **Recovery Reference**: Uses origin_id pattern "29:advance_id:schedule_id" for traceability
